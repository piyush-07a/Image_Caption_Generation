What is Image Captioning?

Image captioning is a multimodal AI task that sits at the intersection of Computer Vision and Natural Language Processing (NLP). Given an image, the model generates a coherent, accurate description of what's happening in the scene.

The model must simultaneously perform multiple complex tasks:

Encoder-Decoder Architecture

Image captioning uses an encoder-decoder architecture — the same design used in machine translation. The encoder processes the input (image) into a rich representation, and the decoder converts that into output (text).

ENCODER-DECODER ARCHITECTURE
📷 IMAGE ENCODER (Vision Transformer)
Image (384×384) → Patch Embed (576 patches) → ViT ×12 Layers (Self-Attention) → Features (577×768)
↓
🔍 CROSS-ATTENTION
"Which parts of the image matter for this word?"
↓
📝 TEXT DECODER (Transformer)
[START] → Decoder ×12 Layers (Self-Attn + Cross-Attn) → LM Head → Next Token

How Text Generation Works

The decoder generates text autoregressively — one word at a time:

  1. Step 1: Input [START] token → Model predicts "A"
  2. Step 2: Input [START] A → Model predicts "dog"
  3. Step 3: Input [START] A dog → Model predicts "playing"
  4. Step 4: Continue until model predicts [END] token

Vision Transformer (ViT)

ViT Processing Steps

  1. Divide: Split image into 576 patches (24×24 grid)
  2. Embed: Linear projection converts each patch to 768-dim vector
  3. Position: Add positional encodings (model needs to know where each patch is)
  4. CLS Token: Prepend special [CLS] token (contains global image summary)
  5. Transform: Process through 12 transformer layers with self-attention

Cross-Attention Mechanism

Cross-attention is the bridge between vision and language. It allows the text decoder to dynamically "look at" different parts of the image while generating each word.

The Intuition 👀

Imagine describing a photo to a friend:

  • When you say "dog" → your eyes focus on the dog
  • When you say "beach" → your eyes scan the background
  • When you say "ball" → your eyes find the ball

Cross-attention does exactly this — it computes attention weights that determine how much each image patch influences each generated word.

The Mathematics

Attention(Q, K, V) = softmax(QKT / √dk) × V
Component Source Role
Q (Query) Text decoder "What am I looking for?"
K (Key) Image encoder "What does each patch contain?"
V (Value) Image encoder "What information should I extract?"
Generating word after "A dog playing..."
Query from decoder: "What should come next?"
ATTENTION SCORES (per patch)
Patch 1 (sky): 0.01 ← Low
Patch 50 (grass): 0.02 ← Low
Patch 150 (dog): 0.15 ← Medium
Patch 200 (ball): 🎾 0.45 ← HIGH!
Patch 300 (tree): 0.01 ← Low
✓ Result: Focus on ball → Predicts "fetch"

BLIP Model

BLIP (Bootstrapping Language-Image Pre-training) from Salesforce Research is a state-of-the-art vision-language model that we use for this workshop.

Specification Value

Inference Speed ~100ms (GPU) / ~5s (CPU)

Why BLIP?

✅ Advantages

  • Fits on free Colab GPU

⚠️ Limitations

  • Trained on natural images

  • CPU inference is slow
  • No fine-grained control

Generation Parameters

How we generate text significantly affects output quality. There are two main strategies:

🎯 Beam Search

  • Deterministic (same input = same output)
  • Explores multiple candidates
  • More fluent, coherent
  • Can be repetitive
  • Controlled by num_beams

🎲 Sampling

  • Stochastic (adds randomness)
  • Different outputs each time
  • More creative, diverse
  • Can be incoherent
  • Controlled by temperature

Parameter Reference

Parameter Range Low Value High Value
num_beams 1-10 Fast, greedy Thorough, slower
temperature 0.1-2.0 Conservative Creative/random
top_p 0.5-1.0 Restricted More diversity
max_length 10-100 Short captions Detailed captions
💡 Recommended Settings

For accuracy: num_beams=5, do_sample=False

For creativity: do_sample=True, temperature=0.8

🎛️ Hyperparameters Deep Dive

Understanding hyperparameters is crucial for controlling caption generation. Each parameter affects how the model selects the next word in the sequence.

max_length Integer

What it is: The maximum number of tokens (words/subwords) the model can generate in a caption.

How it works: The model stops generating text when it either produces an [END] token or reaches this length limit, whichever comes first.

max_length=20 → "a dog playing fetch on the beach" max_length=50 → "a dog playing fetch on the beach with a red ball while the sun sets in the background"

Typical values: 20-50 for concise captions, 50-100 for detailed descriptions

⚠️ Watch out!

Too short → incomplete sentences. Too long → repetitive or hallucinated details.

min_length Integer

What it is: The minimum number of tokens required before the model is allowed to generate an [END] token.

How it works: Prevents overly short captions by forcing the model to continue generating even if it wants to stop early.

Without min_length → "a dog" With min_length=10 → "a dog playing with a ball on the beach"

Typical values: 10-15 tokens

Use case: Ensures captions are sufficiently descriptive and not truncated.

temperature Float (0.0-2.0)

What it is: Controls the randomness of predictions by scaling the logits before applying softmax.

How it works: Temperature divides the model's raw scores (logits) before converting them to probabilities. Lower values make the distribution "sharper" (more peaked), higher values make it "flatter" (more uniform).

The Mathematics:

P(word) = softmax(logits / temperature)
temperature=0.1 → [0.9, 0.08, 0.02] ← Very confident, picks "dog" temperature=1.0 → [0.6, 0.25, 0.15] ← Balanced distribution temperature=2.0 → [0.4, 0.35, 0.25] ← Flatter, more random
Value Effect Output Style
0.1-0.5 More deterministic Safe, predictable, accurate
0.7-1.0 Balanced Natural variation
1.5-2.0 More random Creative, diverse, risky
💡 Pro Tip

Temperature only matters when do_sample=True. With beam search (do_sample=False), temperature has no effect.

num_beams Integer (1-10)

What it is: The number of parallel sequences (beams) explored during beam search.

How it works: Instead of greedily picking the best word at each step, beam search keeps track of multiple candidate sequences and explores them in parallel, then selects the overall best sequence.

Beam Search with num_beams=3
Step 1: [START]
├─→ "a" (score: -0.5)
├─→ "the" (score: -0.8)
└─→ "one" (score: -1.2)
Step 2: Expand top 3
From "a":
├─→ "dog" (total: -1.0) ← BEST PATH
├─→ "cat" (total: -1.3)
└─→ "bird" (total: -1.8)
From "the":
├─→ "dog" (total: -1.5)
└─→ "beach" (total: -1.7)
Keep top 3 beams and continue generating...
num_beams Search Strategy Quality vs Speed
1 Greedy (no beam search) Fastest, lowest quality
3-5 Moderate exploration Good balance
8-10 Thorough exploration Best quality, slowest

Trade-off: Higher beams = better captions but slower inference. Computational cost increases linearly with num_beams.

top_k Integer

What it is: Limits sampling to only the top-k most probable tokens at each step.

How it works: Before sampling, the model filters out all but the k highest probability tokens, then renormalizes and samples from this restricted set.

All vocabulary (30,522 words) → Top-50 words → Sample from these 50
Value Effect
top_k=10 Very restricted, conservative choices
top_k=50 Standard setting, balanced
top_k=100 More diversity, some unusual words

Use case: Prevents the model from occasionally selecting very low-probability, nonsensical words.

top_p Float (0.0-1.0)

What it is: Also called "nucleus sampling" – samples from the smallest set of tokens whose cumulative probability exceeds p.

How it works: Instead of a fixed number of tokens (top_k), top_p adapts dynamically. It includes tokens until their cumulative probability reaches the threshold p.

Token probabilities: [0.5, 0.3, 0.1, 0.05, 0.03, 0.02...] top_p=0.9 → Includes tokens until sum ≥ 0.9 → Uses first 3 tokens (0.5 + 0.3 + 0.1 = 0.9) top_p=0.95 → Uses first 4 tokens (0.5 + 0.3 + 0.1 + 0.05 = 0.95)
Value Behavior
0.8-0.9 Conservative, high-quality outputs
0.92-0.95 Standard range, good balance
0.98-1.0 Maximum diversity, allows rare words
🔄 top_k vs top_p

These are often used together! The model first applies top_k filtering, then applies top_p to the remaining tokens. You can use one or both.

do_sample Boolean

What it is: Determines whether to use sampling (stochastic) or greedy/beam search (deterministic).

How it works: This is the master switch that controls the generation strategy.

do_sample=False

  • Uses beam search or greedy decoding
  • Always picks highest probability token
  • Same input → same output (deterministic)
  • More fluent and coherent
  • Can be repetitive or generic

do_sample=True

  • Uses sampling-based generation
  • Probabilistically selects tokens
  • Same input → different outputs
  • More diverse and creative
  • Controlled by temperature, top_k, top_p
repetition_penalty Float (1.0-2.0)

What it is: Penalizes tokens that have already appeared in the generated sequence to reduce repetition.

How it works: For tokens already generated, their logits are divided by this penalty value, making them less likely to be selected again.

Without penalty → "a dog playing with a dog and a dog" With penalty=1.2 → "a dog playing with a ball on the beach"
Value Effect
1.0 No penalty (default)
1.1-1.3 Mild penalty, reduces obvious repetition
1.5-2.0 Strong penalty, forces diversity

Use case: Essential when you notice the model repeating the same words or phrases.

no_repeat_ngram_size Integer

What it is: Prevents n-grams (sequences of n words) from appearing more than once in the output.

How it works: The model tracks all n-grams generated so far and blocks any token that would create a duplicate n-gram.

no_repeat_ngram_size=2 (bigrams): ✗ Blocks: "a dog... a dog" (duplicate bigram) ✓ Allows: "a dog... the dog" (different bigram) no_repeat_ngram_size=3 (trigrams): ✗ Blocks: "on the beach... on the beach" ✓ Allows: "on the beach... on the shore"

Typical values: 2-3. Higher values are too restrictive.

⚙️ Hyperparameter Combinations

Recipe 1: Maximum Accuracy

generate( max_length=30, num_beams=5, do_sample=False, repetition_penalty=1.2 )

Best for: Production systems, accessibility tools, critical applications

Recipe 2: Creative & Diverse

generate( max_length=50, do_sample=True, temperature=0.8, top_p=0.95, top_k=50 )

Best for: Creative applications, generating multiple caption options

Recipe 3: Balanced

generate( max_length=40, num_beams=3, do_sample=True, temperature=0.7, repetition_penalty=1.1 )

Best for: General purpose, good quality with some variation

Evaluation Metrics

No single metric captures caption quality. We use two complementary approaches:

📊 BLEU Score

  • Measures n-gram overlap
  • Fast and interpretable
  • Industry standard
  • Misses synonyms
  • "dog" vs "canine" = 0 overlap

🧠 Semantic Similarity

  • Compares meaning
  • Uses embeddings
  • Catches paraphrases
  • Slower (needs model)
  • "dog" vs "canine" = high score

When Metrics Disagree

Test Case BLEU Semantic Interpretation
Identical sentences 1.0 1.0 Both agree ✓
Paraphrases 0.2 0.9 Semantic wins — same meaning
Word order change (different meaning) 0.8 0.3 BLEU fooled!
Completely different 0.0 0.1 Both agree ✓
⚠️ Key Insight

Always use both metrics together. BLEU catches surface-level matching, semantic similarity captures meaning. Neither alone is sufficient!

GIGO: Garbage In, Garbage Out

GIGO is critical for multimodal AI. Unlike text where typos are obvious, image quality problems are subtle. A blurry or dark image produces poor captions without obvious errors.

Quality Checks

Check Threshold Why It Matters
Resolution Min 100×100 px Low-res images lose object detail
Aspect Ratio Max 3:1 Extreme ratios indicate cropping issues
Brightness 30-240 (0-255) Too dark/bright loses information
Color Variance Min std of 15 Low variance = blank/corrupted image

Confidence Estimation

Even with good inputs, models can be uncertain. We estimate confidence by:

  1. Generate multiple captions with sampling enabled
  2. Measure consistency across samples
  3. High consistency = confident model
  4. Divergent samples = uncertain, flag for review
# Confidence estimation via sampling samples = [generate_caption(image, do_sample=True) for _ in range(5)] # If all samples agree → confident # If samples diverge → uncertain consistency = average_pairwise_similarity(samples)
